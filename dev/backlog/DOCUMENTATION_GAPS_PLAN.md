## 1. Summary of the audit

The **reference** layer is in good shape: `reference/workflow-schema.md`,
`reference/settings.md` and `reference/run-files.md` are generated from the schemas, and all 159
settings defaults match `CTRLYOKE_SETTINGS_DEFAULTS`.

The **guide** layer is the gap. Almost nothing a user sees in the dashboard is documented. That
includes run controls, the output pane, undo, Dry Run, the terminal, history search, the settings
drawer, the hosted/mobile dashboard, the workspace viewer, commit messages, notifications and
usage tracking. Several workflow features exist only as schema rows with no how-to: script steps,
variables, worktrees, secrets, error handling, permissions, MCP servers, hooks and coordination.
There were no screenshots anywhere in `docs/` at the time of the audit. As of 2026-10-10 only
`workflows/properties-panel.md` and `pro/mobile-setup.md` have any.

### Already corrected in the audit commit (not repeated below)

All hand-written pages were checked against code and fixed in place. The largest corrections:

- **CLI:** `cli/ctrlyoke.md` listed `--resume`, `--new-session` and `--allow-all-tools`, which
  don't exist. Added `rerun`, `append`, `continue`, `commit`, `trust-secret-grants`, `--dry-run`,
  `--permission-mode`, exit codes, the `--json` envelope and env vars.
- **Commands:** `reference/commands.md` listed three commands that don't exist. Added the ~12
  real ones it was missing, plus the context-menu and keybinding tables.
- **Sessions:** every `sessionId` example in `workflows/session-management.md` was missing
  `resumeSession: true`, so none of them resumed a session.
- **End conditions:** `workflows/end-conditions.md` had the retry semantics wrong. Retries depend
  on having a retry prompt, not on `onFail: retry`.
- **Parallel groups:** the docs claimed parallel members can't use the built-in `ctrlyoke` MCP
  server. That rule was removed by `PARALLEL_STEP_MUTABILITY_PLAN.md`.
- **MCP tools:** `reference/mcp-tools.md` was missing the four coordination tools and the
  parameters and return shapes. `cli/ctrlyoke-mcp.md` wrongly implied standalone use without
  `CTRLYOKE_WORKING_FILE`.
- **Harness pages:**
  - wrong model IDs (`claude-sonnet-4.5`, `gpt-5.2-codex`)
  - wrong Antigravity minimum version
  - a false "all harnesses have identical capabilities" claim
  - OpenCode permissions described as mode-only (they are pattern-enforced)
  - Codex and Antigravity permission-flag mappings added
- **Guide pages:** wrong VS Code and Node minimum versions; the panel opens in the secondary side
  bar; `server.certPath` should be `server.tls.certPath`; internal jargon and a public link to
  `dev/backlog/RUN_EXPORT_PLAN.md` were removed; wrong GitHub URL (`nhickster` should be
  `FuzzyNova`).
- **Workflow authoring:** `.prompt.md` frontmatter is **not** parsed. Documented the
  path-vs-inline rule for `prompt:`, where context references resolve, the backtick-fence rule,
  the full built-in template list and agent/skill discovery order.
- **Reference partials:** a wrong `trust-external-roots <file>` signature; the settings merge
  rules (external roots are unioned, CLI flags overlay both files); a new run-files location
  table. Parallel-group rules and step `_runtime` semantics went into the schema descriptions,
  and the generator now names composed (`allOf`) sections, so neither needs a partial.

## 6. Keeping docs accurate (guardrails)

The audit found the same classes of drift again and again. Automate the ones that are cheap.
**Status 2026-10-10:** all six items are done. `scripts/check-docs-content.mjs` runs at
the end of `check:docs` (so also in `predocs:build`), with unit tests in `test:packaging`. Item 1
shipped as a two-way **drift check** rather than a generator: the commands page is mostly curated
prose (submenu behaviour, "where it appears", Save As), so generating it would mean moving nearly
all of it into partials for little gain. The check fails when a contributed command or keybinding
has no row, or a documented `ctrlyoke: …` command isn't contributed, which is exactly the
three-phantom-commands failure. Item 5 checks Copilot, Claude and Codex models only; OpenCode,
Qwen and Antigravity model lists are discovered at runtime. The first run found one false positive
(an MCP `append_step` argument in `mcp-tools.md`, now opted out) and no real defects. Item 2 is
also a drift check, not a generator, for the same reason. It walks the built CLI's `--help`
tree (about 3 s, run in parallel) and fails when a command has no `ctrlyoke <command>` heading
(subcommands may share their parent's), when an option is in neither its command's section nor
the shared `run` options table, or when `cli/ctrlyoke.md`, `cli/index.md`, `cli/ci.md`,
`cli/server.md` or `troubleshooting/common-errors.md` names a flag no command has. Its first run
found two real gaps, both fixed: `trust-external-roots` had no section of its own, and
`secret rm --yes` was undocumented.

1. **Generate `reference/commands.md`** from `package.json` `contributes.commands`, `menus` and
   `keybindings`, the same way `generate-schema-docs.mjs` does. Add hand-written partials for the
   descriptions and include it in `check:docs`. Three nonexistent commands had been listed for
   months.
2. **Generate the CLI flag tables** in `cli/ctrlyoke.md` from the commander definitions
   (`CliRunCommandDefinitions.ts`, `SecretCommandDefinitions.ts`, `cli.ts`), with partials for
   the prose. Three nonexistent flags had been documented.
3. **Validate doc examples.** Add a `node --test` script (in `test:packaging`) that extracts every
   fenced `yaml`/`json` block under `docs/workflows/`, `docs/guide/` and `docs/examples/` whose
   content has `steps:`, `prompt:` or `type: script`, and validates it with the same ajv setup
   `PromptFileParser` uses. Allow an opt-out comment (`<!-- no-validate -->`) for deliberate
   fragments. The audit found invalid model IDs and stale-path examples by hand.
4. **Lint public docs for internal leakage.** `generate-schema-docs.mjs` already has
   `INTERNAL_DESCRIPTION_PATTERNS`. Apply the same check (`dev/` links, `ClassName.method()`
   references, `copilot-chat`) to all hand-written `docs/**/*.md` pages in `check:docs`.
5. **Model IDs in examples** should come from `ModelConstants.ts`. The check in item 3 can warn
   on a `model:` value outside the harness's known list.
6. Add a rule to `.github/instructions/` (the right file per the routing table): a
   behaviour change that touches a user-visible surface updates the matching `docs/` page in the
   same commit, the same way `agentGuidance` already requires tests.
