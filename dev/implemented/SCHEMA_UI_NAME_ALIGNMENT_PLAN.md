# Schema ↔ UI Name Alignment Plan

**Status: implemented (2026-09-25).** Every phase landed, including C6 (resolved by the §3b shared-definition refs).

## Problem

The words the dashboard shows often differ from the property names and enum values
you write in `.ctrlyoke.yaml` / `.ctrlyoke/settings.json`, so you can't map a
control to its YAML. The trigger case (since fixed by renaming the schema value to `none`): the workflow schema's `toolPermissions.mode`
enum is `dangerouslyAllowAll | allowAll | custom | passthrough`, but the dropdown
shows **"None"**. Internally `PERMISSION_MODES.NONE = "none"` exists and nothing
references `passthrough`.

The audit found that this is more than a labelling problem. In several places the
schema, the TS constants, the runtime, and the UI each use a different value for
the same concept, and at least one of those gaps changes behaviour (§3, H1).

No control in the dashboard currently shows the schema property name or value in a
tooltip or ARIA label. The step-override badges in `WorkflowStepsPanel.tsx`
(`title: "priorContext: …"`, lines 944–1137) are the only surface that does this.
They are the model to generalize.

## 1. Policy (Nathan's rule)

1. **Default: the label is the schema word, humanized.** `stopWorkflow` → "Stop Workflow".
   Drop words from the label only when a heading already supplies them (for example,
   "Sandbox mode" under a Codex heading).
2. **Same concept → same word; different concept → different word.** Before choosing a
   label or a schema value, check whether a sibling value means the same thing. If it
   does, use its word, and rename the schema value if that is what disagrees (H3, H8).
   A shared word is only a problem when the concepts actually differ. The same holds
   across surfaces: one value gets one label everywhere it appears (H13).
3. **Aliases are allowed with a reason.** Example: "Dangerously Allow All (yolo)",
   because people know the mode as yolo. An alias must still obey rule 2.
4. **Uniform rule, no exceptions.** Every schema-backed control and every option
   gets the following, whether or not its label matches:
   - A **tooltip** (`title`) that ends with `property: <path>` for fields, or
     `property: <path> = <value>` for options.
   - An **accessible name** that starts with the visible label, to satisfy WCAG
     2.5.3 "label in name", and then adds the property:
     `"<Label>, property <path>"` / `"<Label>, <path>: <value>"`.
   - Pseudo-options that do not correspond to a schema value (Inherit / None / Custom
     / Default (…)) state the YAML they produce instead. Examples: `omit toolPermissions`,
     `toolPermissions: null`, `priorContext: [1,2]`.
5. **Paths are file-relative.** Workflow controls show the workflow path
   (`toolPermissions.mode`). Settings controls, including the Workflow Defaults pages,
   show the settings path (`defaults.toolPermissions.mode`).
6. **Schema renames are allowed** because the project is pre-release. Change the
   schema word instead of the UI label when the schema word is the worse one: negative
   booleans, inconsistent sibling vocabularies, or keys that disagree with their own
   description or behaviour. Every schema rename must be followed by
   `npm run generate-schema-docs` and `npm run generate-schema`.

### 1.1 The "nothing" vocabulary

Rule 2 applied to the most common concept: "don't do this thing". Every control uses
one of these, and **"Off" is not used as an option label anywhere**.

| Word                                 | Means                                                                                     | Writes                                                                                                               | Used for                                                                                                                                                                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **None**                             | Explicitly _none of this thing_. It overrides anything inherited.                         | Whatever the field's schema uses: `false`, `null`, `""`, `[]`, `"none"`. The tooltip always states the literal (M8). | Every "which X?" picker or filter: `worktree`, `toolPermissions`, `agent`, conditions, MCP/skills/additionalArgs, `priorContext` (already has a `none` keyword), `toastLevel`, `notifications.events.*`, `ui.stepColorMode` |
| **Never**                            | A "when?" question answered with no time. Only where the sibling values are about timing. | `never`                                                                                                              | `terminal.mobileControlBar` (`auto`/`always`/`never`), `notifications.browser.mode` (`connectedOnly`/`push`/`never`)                                                                                                        |
| **Inherit (&lt;resolved label&gt;)** | The property is omitted, so the value comes from defaults.                                | nothing (`omit <path>`)                                                                                              | Every inherit / default pseudo-option (M19)                                                                                                                                                                                 |
| _(toggle)_                           | A real on/off setting.                                                                    | `true` / `false`                                                                                                     | Booleans render as a checkbox labelled with the humanized property name. No None / Off / Yes / No options.                                                                                                                  |

The distinction users must learn is **None vs Inherit**, not None vs Off: None is an
explicit "no" that beats a default, Inherit leaves the property out. Every tooltip
therefore states which one it is. A boolean-shaped literal that is one choice of a
mode picker (`worktree: false` / `true`) is labelled by the mode (None / Managed), not
by the literal.

### New pieces

1. **`src/types/SchemaUiMetadata.ts`** holds the typed metadata, shared by the extension and the webview:
   ```ts
   interface SchemaFieldMeta {
     path: string;
     label: string;
     alias?: { reason: string };
   }
   interface SchemaOptionMeta<V extends string> {
     value: V;
     label: string;
     alias?: { reason: string };
     visual?: { codicon: string; color: string }; // absorbs PERMISSION_MODE_VISUALS
   }
   // Record<V, …> keyed by the existing constant so tsc enforces completeness:
   export const PERMISSION_MODE_OPTIONS_META: Record<
     PermissionMode,
     SchemaOptionMeta<PermissionMode>
   >;
   ```
   One table per enum. `COMPARE_SOURCE_LABELS`, `SCRIPT_OPERATOR_LABELS`, `HOOK_EVENT_METADATA`,
   `EXECUTION_MODE_OPTIONS`, `WORKTREE_MODE_OPTIONS`, `PRIOR_CONTEXT_KEYWORD_LABELS`,
   `ERROR_ACTION_OPTIONS`, and every inline `options={[…]}` array listed in §4 move into it.
   `toSelectOptions(meta, path)` produces `SelectOption[]`.
2. **Descriptions come from the schema, not a third copy.** Add
   `scripts/generate-schema-ui-descriptions.mjs`, which emits
   `src/types/generated/SchemaDescriptions.ts` (path → `description`, enum list), with
   a `--check` mode. It runs from `precompile` like the other `generate-*` scripts, and
   `npm run check:docs` gains the check. Tooltip bodies then come from the same text as
   IntelliSense hovers and the generated reference docs. That lets us delete
   hand-written duplicates such as `WORKTREE_MODE_HELP_TEXT` (`DashboardConstants.ts:2068`),
   which repeats `worktreeConfig`'s branch descriptions. Labels stay in TS because a
   schema `description` is prose, not a label.
   - _Considered and rejected for now:_ putting labels in the schema as `x-ctrlyoke-label`
     / `x-ctrlyoke-enumLabels`. That would be a single source, but `PromptFileParser`'s
     Ajv (`new Ajv({ allowUnionTypes: true })`, `PromptFileParser.ts:66`) runs in
     strict mode and rejects unknown keywords unless they are registered. The labels
     would also ship in the user-facing schema and YAML. Revisit if the TS table drifts.
3. **`src/ui/webview-react/utils/schemaPropertyLabels.ts`** provides
   `schemaTitle(path, value?)` and `schemaAriaLabel(label, path, value?)`. They are the
   only functions that format the `property: …` text.
4. **Wiring:**
   - `CustomSelect` gets a `schemaPath` prop. The trigger and each option get
     title and aria through the helpers.
   - `FormField`, the `PropertiesDrawer` `<label>` blocks, `ScriptConditionEditor`,
     `ErrorBehaviorEditor`, `HooksEditor`, `McpServerForm` and `PriorContextSelect`
     take the path explicitly.
   - `SettingInputRow` / `SettingToggleRow` use the `path` they already receive.
     Today they render no tooltip at all.

## 3b. Settings `defaults` reuse workflow definitions

`settings-schema.json` `defaults.*` hand-copies the workflow schema's value shapes, and the
copies have drifted. That drift caused H4, and it is why H3 has to be edited "in both schemas".

**Do not embed the whole workflow schema as `defaults`.** Choosing which properties get a
default is a real decision, for three reasons. Most workflow properties cannot have one
(`steps`, `prompt`, `name`, `sessionId`, `_runtime`, …). Some defaults need a different shape
(`model` → `models.<harness>`, `additionalArgs` → `additionalArgs.<harness>`,
`trustedExternalRoots` → `permissions.trustedExternalRoots`). And draft-07 cannot close an
`allOf`-composed object without `unevaluatedProperties`, so `defaults` would stop rejecting
typos. The key list stays explicit. The _values_ get shared.

Drift found (verified against the current schemas):

| Default                                                    | Drift                                                                                                                                                                                                                                                                   |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `endCondition` / `preCondition`                            | Closed (`additionalProperties: false`) but missing `env` and `shell`. `ScriptProperties` (`CtrlYokeTypes.ts`) and the workflow schema accept both, so a valid default is flagged. The `onPass`/`onFail` `default`s and the `timeout` fallback wording are also missing. |
| `priorContext`                                             | `type: string` with no enum; `CtrlYokeSettings.defaults.priorContext` is `string`, not `PriorContext`.                                                                                                                                                                  |
| `hooks`                                                    | `items: {type: object, additionalProperties: true}`, so hooks get no validation. The workflow schema has `userHookConfig`.                                                                                                                                              |
| `mcpServers`                                               | Resolved: items `$ref` the workflow `mcpServerEntry` (C6).                                                                                                                                                                                                                  |
| `agent` / `skills`                                         | The name `pattern` is missing.                                                                                                                                                                                                                                          |
| `toolPermissions.mode`, `errorBehavior.onError`, `harness` | Duplicated enums (H4 was this; H3 needs two edits).                                                                                                                                                                                                                     |
| `worktree`                                                 | A different shape (H2b).                                                                                                                                                                                                                                                |

Fixes:

1. **Done.** Defaults now reference shared workflow definitions through sibling-schema `$ref`s. Both
   schemas ship to `out/schemas/`, so `workflow-schema.json#/definitions/<name>` resolves in VS Code's
   JSON language service. The inline `oneOf`s in `executionProperties` (`toolPermissions`,
   `priorContext`, `agent`, `skills`, `secrets`) were lifted into named definitions and reused from
   `defaults`, along with `errorBehavior`, `userHookConfig` (`hooks.items`) and `harnessId`. The
   condition and error-behavior defaults use named nullable wrappers to preserve their explicit
   `null` disable values.
   Workflow `endCondition` / `preCondition` are now closed. Draft-07 does not apply
   `additionalProperties` across `allOf`, so each condition declares the shared `scriptProperties`
   names locally while keeping their detailed constraints on the shared definition. The MCP item ref
   uses a named string-or-config union so registry IDs remain valid alongside inline server objects.
   Defaults-specific descriptions remain sibling `description` values.
2. **Done.** The docs resolver follows sibling schema references, and its tests cover that path.
   `NotificationSettings.test.ts` registers `workflow-schema.json` with Ajv before compiling the
   settings schema. No production Ajv validates `settings.json`; the schema is wired through
   `package.json` `jsonValidation`.
3. **Done.** A defaults coverage test walks `executionProperties` and `workflowOnlyProperties`. Every key must be
   in `defaults`, mapped to a differently shaped default (`model → models`, `additionalArgs →
additionalArgs.<harness>`, `trustedExternalRoots → permissions.trustedExternalRoots`), or on an
   opt-out list with a reason (`sessionId`, `vars`, …). This follows the same pattern as `UI_CONTROL_OPTOUTS`
   and the existing `defaults.*` coverage test in `WebviewSettingsSync.test.ts`. A new workflow property
   then fails CI until someone decides about its default.
4. **Done.** `CtrlYokeSettings.defaults.priorContext` is typed as `PriorContext`. The other
   `defaults` fields already reuse the workflow types.

## 5. Phases

**Execution order.** The phases run in the order 0.5 → 0 → 4 → 1 → 2/3 → 5. Phase 4, the schema
renames, runs _before_ the mechanism so the meta tables and parity tests are written once against
the final values. The other order would mean writing `never` / `off` rows and then renaming them,
and the "nothing vocabulary" test could not pass until Phase 4 landed. Phases 2 and 3 run together,
one surface at a time, because moving an option array into its meta table and fixing its label is
the same edit.

0. **Correctness (H3).** Resolved: H1, H1b, H4 and H3 (schema `passthrough` → `none`, spawn-time `none` handling, settings enum, and `onError: stopWorkflow`).
   **0.5 Shared defaults (§3b).** Resolved: workflow definitions are shared through settings `defaults`,
   cross-file schema docs and Ajv coverage are in place, every workflow property is accounted for in the
   defaults coverage test, and `defaults.priorContext` uses `PriorContext`. Both schema artifacts are regenerated.
1. **Mechanism — done.** Typed `SchemaUiMetadata.ts` option tables, generated `SchemaDescriptions.ts` plus its `--check`, and `schemaPropertyLabels.ts` provide the shared metadata. `CustomSelect` now accepts `schemaPath` and adds property-aware trigger/option tooltips and accessible names. `FormField` carries workflow-relative paths, and `SettingInputRow` / `SettingToggleRow` use settings paths for titles and accessible names. Rendered Vitest coverage checks all four surfaces.
2. **Relabel HIGH + MEDIUM** (§4.1, 4.2, 4.4, 4.5). UI-label fixes only, following the §1.1 vocabulary: no "Off" option labels, "None" for every "none of this thing" choice, "Never" only for timing enums, `Inherit (<label>)` for omission, and no Yes/No options. **Settings rows in §4.4–4.6 handled.**
3. **Migrate option arrays** (§4.7 C7, all inline `options={[…]}` in §4) to the meta tables. Delete the duplicates, including `WorkflowStepsPanel`'s short maps (they can use `meta.short`) and `PERMISSION_MODE_VISUALS`. Wire the path through the remaining editors (SCE, EBE, HooksEditor, McpServerForm, PriorContextSelect, quick pickers). Standardize the Inherit label (M19). **Settings surface handled.**
4. **Schema renames**:
   - Keys: H5 `ui.showCostEstimates`, H7 `execution.contextResolutionFailure`, H10 `permissions.trustedExternalRoots`, H12 `server.autoStart`, M11 `commit.systemPrompt`.
   - Resolved H8: `notifications.events.*`, `notifications.toastLevel`, and `ui.stepColorMode` use `none` / "None"; browser notifications and the mobile control bar retain `never` / "Never".
